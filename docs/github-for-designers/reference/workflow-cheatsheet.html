PR workflow cheat sheet

The whole loop on one page. Print it and keep it by your desk.

Author

Step Command or click
1. Latest main git switch main · git pull · pnpm install
2. Branch git switch -c design/short-description
3. Change pnpm dev → localhost:3000. Tokens from tokens.css, components from HeroUI.
4. Check pnpm format && pnpm lint && pnpm typecheck
5. Commit git status · git add -A · git commit -m "Say what it does"
6. Push + PR git push -u origin design/short-description · gh pr create --web
Fix feedback Edit → steps 4–5 → git push
7. Merge Squash and merge → Delete branch (after one approval)
8. Clean up git switch main · git pull · git branch -D design/short-description

Reviewer

Do Where
Try it Vercel bot's Preview link on the PR, or gh pr checkout <number> then pnpm dev
Comment on a line Files changed → hover line → blue + → Start a review
Propose an exact edit Suggestion icon in the comment box
Finish Review changes → Comment / Approve / Request changes → Submit review

What designers look for in review

  • Does the preview match the intent in the PR description and screenshots?
  • Are values tokens from tokens.css, not raw hex or pixel numbers?
  • Does it hold up in each scenario it touches (Stalled, Looping)?
  • Is the PR one change? If not, ask to split it.

Oops

Situation Fix
Which branch am I on? git status (first line)
Made changes on main by mistake (not committed) git switch -c design/new-name: your edits come with you
Want to throw away uncommitted edits to a file git restore path/to/file (can't be undone)
Typo in the last commit message, not pushed yet git commit --amend -m "Better message"
git pull says "conflict" Stop and ask an engineer or Claude. Don't force anything.
