Lesson 0001 · GitHub for designers

Your first pull request on project-waymo

Get the latest code, change one thing, and get it merged into main after a teammate reviews it.

Every change to the cabin prototype follows the same loop, called GitHub flow. You never edit main directly. You work on a branch (your own copy), open a pull request (PR) asking for it to be merged, and a teammate reviews it first. New words are defined in the glossary.

One-time setup

You need git, pnpm and the GitHub CLI installed, and collaborator access to the repo. Then: 

gh auth login                                  # sign in to GitHub once
gh repo clone tnamdevnote/project-waymo
cd project-waymo

The loop

The example below tightens the spacing on the arrival pill. Swap in your own change.

  1. Get the latest main Other people have merged work since you last looked. Start from their latest version. 
    git switch main
git pull
pnpm install                                   # picks up any new packages
  2. Start a branch Name it design/ plus a few words about the change, so anyone can tell what it is from the name. 
    git switch -c design/arrival-pill-spacing

    One branch per change. If you also want to reword the Pull over sheet, that goes on its own branch and its own PR. Small PRs are faster to review and easier to undo (GitHub flow).

  3. Make the change and look at it 
    pnpm dev                                       # open http://localhost:3000
    Read DESIGN.md first. Use only the tokens in src/app/tokens.css and components from @heroui/react.
  4. Check it These three commands fix formatting and catch mistakes before anyone else sees them. 
    pnpm format && pnpm lint && pnpm typecheck
  5. Commit A commit is a saved snapshot with a message. Check what changed, stage it, then commit. 
    git status                                     # which files changed?
git add src/components/features/cabin-screen/CabinScreenRoot.tsx
                                               # or: git add -A for everything
git commit -m "Tighten spacing on the arrival pill"

    Write the message as what the change does: "Tighten spacing on the arrival pill", not "fixes" or "wip".

  6. Push and open the pull request 
    git push -u origin design/arrival-pill-spacing
gh pr create --web                             # opens the PR form in your browser
    In the description, say what changed and why, add before/after screenshots, and say how to see it ("start the Stalled scenario"). A minute or two later the Vercel bot comments on the PR with a preview link: your branch, running on the web, for reviewers to click.
  7. Review (the reviewer's side) Open the Vercel preview and try the change. Then go to the Files changed tab:
    • Hover a line, click the blue +, and comment. Click Start a review so your comments go out together.
    • To propose an exact edit (a typo, a token name), click the suggestion icon in the comment box. The author can commit it with one click.
    • Finish with Review changes and pick Comment, Approve, or Request changes.

    Source: GitHub Docs, Reviewing proposed changes

    The author answers feedback by committing and pushing again on the same branch (repeat steps 4–6, skipping gh pr create). The PR updates by itself.
  8. Merge and clean up Once it's approved, click Squash and merge on the PR. This turns all the branch's commits into a single commit on main (GitHub Docs, About merges). Then click Delete branch, and on your machine: 
    git switch main
git pull
git branch -D design/arrival-pill-spacing      # capital D: squashed branches need it

House rule: GitHub doesn't currently stop anyone merging without a review on this repo. We still wait for one approval before merging.

Using Claude Code? You can ask it to "create a branch, commit, and open a PR" and it will run these commands. Knowing the loop still matters, so you can tell when something has gone wrong.
